# CoreBank 팀 PR-Agent 사용 가이드 (하이브리드 방식)

## 1. 왜 하이브리드인가

CodeRabbit 무료 한도 문제로 PR-Agent(오픈소스, 개인 API 키 기반)로 전환합니다.
6명 팀, 하루 PR 10개(월 약 250~300건) 기준으로 모든 리뷰를 Sonnet으로 돌리면
월 예산이 쉽게 $20~50대까지 올라갑니다. 반대로 전부 Haiku만 쓰면 미묘한 로직 버그
(특히 원장 기표, 이체 실행 같은 금액/트랜잭션 관련 코드)를 놓칠 위험이 있습니다.

그래서 **평소엔 저렴한 모델로 자동 리뷰하고, 병합 직전 핵심 변경에만 사람이 직접
고성능 모델을 호출**하는 방식으로 갑니다. 월 예산 목표는 **$10 이내**입니다.

## 2. 자동으로 일어나는 것 (신경 안 써도 됨)

| 시점 | 동작 | 모델 |
|---|---|---|
| PR을 처음 열 때 (`opened`) | `/review` + `/describe` 자동 실행 | Claude Haiku 4.5 |
| PR 재오픈 (`reopened`) | 위와 동일 | Claude Haiku 4.5 |
| PR 열린 상태에서 커밋 push | `/describe`만 자동 실행 (리뷰는 안 돎) | Claude Haiku 4.5 |

- push할 때마다 풀리뷰가 다시 도는 게 아니므로, 커밋을 잘게 나눠 올려도 비용이 튀지 않습니다.
- Haiku 기반 자동 리뷰는 스타일/린트성 지적은 최소화하도록 설정되어 있고, 정확성·보안·트랜잭션 처리·마이그레이션 위주로 코멘트를 답니다.

## 3. 사람이 직접 해야 하는 것

### 3-1. 언제 Sonnet 수동 리뷰를 요청하나

아래 중 하나라도 해당하면, **병합(merge) 직전에 반드시** 수동으로 Sonnet 리뷰를 한 번 더 돌리세요.

- 금액/잔액 계산, 원장 기표(전표) 로직을 건드린 PR
- 이체 실행, 이체 결과 조회 등 트랜잭션 흐름이 바뀌는 PR
- DB 스키마/마이그레이션 변경이 포함된 PR
- 동시성(락, 트랜잭션 격리) 관련 코드
- Haiku 자동 리뷰가 이미 여러 번 이슈를 지적했는데 계속 재발하는 PR

반대로 아래는 Haiku 자동 리뷰만으로 충분합니다. 굳이 Sonnet 안 돌려도 됩니다.

- 문서/주석 수정, 리팩토링(로직 변경 없음)
- 테스트 코드 추가/수정
- 단순 API 스펙·DTO 필드 추가

### 3-2. Sonnet 수동 리뷰 실행 방법

**어디에 입력하나:**

1. GitHub에서 해당 PR 페이지로 들어갑니다.
2. 상단 탭 중 **`Conversation`** 탭(기본으로 열리는 탭, PR 설명과 코멘트들이 쭉 나열된 화면)으로 이동합니다. `Files changed` 탭 안의 특정 라인에 다는 리뷰 코멘트가 아니라, **PR 전체에 대한 일반 코멘트**입니다.
3. 맨 아래 코멘트 입력창(다른 사람 PR에 댓글 달 때 쓰는 그 창)에 아래 명령어를 그대로 붙여넣습니다.
4. **`Comment`** 버튼을 눌러 등록합니다. (Approve/Request changes 버튼 말고 그냥 코멘트로 남기는 겁니다.)
5. 등록 후 몇 초~수십 초 내로 PR-Agent 봇이 별도 코멘트로 리뷰 결과를 답니다. (워크플로우가 `issue_comment` 이벤트로 트리거되도록 설정돼 있어서 자동으로 인식합니다.)

```
/review --config.model="anthropic/claude-sonnet-5"
```

코드 제안까지 받고 싶으면 같은 방식으로:

```
/improve --config.model="anthropic/claude-sonnet-5"
```

병합 전 최종 체크 1회로 제한해 주세요. 같은 PR에 여러 번 반복 호출하면 예산이 빠르게 소진됩니다.

## 4. 하지 말아야 할 것

- `auto_improve`를 로컬에서 임의로 `true`로 바꿔서 push할 때마다 `/improve`가 자동으로 돌게 하지 마세요. (가장 토큰을 많이 씀 — 팀 전체 예산에 영향)
- 같은 PR에 Sonnet 리뷰를 반복 호출하지 마세요. 코멘트 반영 후 재확인이 필요하면 변경분만 짚어서 `/ask`로 특정 파일/함수만 질문하는 걸 권장합니다.
- 대용량 자동 생성 코드(QueryDSL Q클래스, Flyway 마이그레이션 SQL 원본)는 리뷰 대상에서 제외되어 있습니다. 이걸 굳이 리뷰에 포함시키려고 설정을 건드리지 마세요.

## 5. 예산 모니터링

- Anthropic Console에 월 $10 하드 리밋이 걸려 있습니다. 한도 도달 시 API 호출이 자동 차단되며, 이 경우 PR-Agent가 리뷰를 못 답니다.
- 한도 근접 알림을 받으면(또는 리뷰가 갑자기 안 달리면) 채널에 공유해 주세요 — Sonnet 수동 호출 빈도를 팀 전체가 줄여야 할 시점입니다.

## 6. 명령어 치트시트

> 아래 명령어는 전부 **PR 페이지 → Conversation 탭 → 맨 아래 코멘트 입력창**에 그대로 입력하고 `Comment`로 등록하면 됩니다. 터미널이나 다른 도구에 입력하는 게 아닙니다.

| 명령어 | 용도 |
|---|---|
| `/review` | 기본 리뷰 (설정된 기본 모델 = Haiku) |
| `/review --config.model="anthropic/claude-sonnet-5"` | 고성능 모델로 최종 리뷰 |
| `/describe` | PR 설명 자동 생성/갱신 |
| `/improve` | 코드 개선 제안 |
| `/ask "질문 내용"` | 특정 부분에 대한 Q&A |
| `/review --config.output_relevant_configurations=true` | 현재 적용된 설정 확인 |

## 7. 자주 나오는 질문

**Q. Haiku 리뷰가 뭔가 놓친 것 같은데?**
A. Haiku는 일부 미묘한 크로스 파일 버그를 놓칠 수 있습니다. 의심되면 그냥 Sonnet 수동 리뷰를 돌리세요. 참고용 안전장치일 뿐, 최종 판단은 항상 리뷰어(사람)입니다.

**Q. PR-Agent 코멘트를 100% 신뢰해도 되나?**
A. 아니요. AI 리뷰는 보조 수단입니다. 특히 원장/이체 도메인은 사람 리뷰어의 최종 승인이 필수입니다 (기존 코드 리뷰어 로테이션은 그대로 유지).
