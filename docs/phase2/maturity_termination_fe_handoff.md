# 만기해지 API ↔ FE 연동 인계 문서 (PH-15 → FE B-3)

> 기준: 2026-10-22 작업 코드 · 관련 이슈: #685
> 구현 계약을 설명하는 문서이며, 머지·배포 완료 여부는 별도로 확인한다.

관련 문서: [PH-15 상세](tasks.md#ph-15-만기--감지--matured-전이--원리금--만기해지-api) · [공통 API 규칙](../api_conventions.md) · [이자 계산 정책](interest_calculation_policy.md) · [GL 분개 패턴](gl_journal_patterns.md) §3-7

## 1. 연동 순서와 지원 범위

1. 계좌 상세 `GET /api/v1/accounts/{accountId}`의 `status`, `maturityDate`로 만기를 안내한다.
2. **해지할 예·적금 계좌**의 비밀번호를 검증해 일회용 토큰을 발급받는다.
3. 새로운 UUID v4 멱등키와 인증 토큰으로 만기해지를 요청한다.
4. 성공하면 지급 결과를 표시하고 상품 계좌·수취 계좌의 상세와 거래내역을 다시 조회한다.

- 본인 소유의 `MATURED` 예·적금이며 계약 만기일이 KST 기준 오늘 이전 또는 오늘이어야 한다. COB 선전환 때문에 `MATURED`만으로 해지 가능 여부를 확정하면 안 된다. 최종 판정은 서버가 한다.
- 가입 상태가 `SUCCESS`, 만기 처리 방식이 `TRANSFER`인 가입만 지원한다. `RENEW` 자동 재예치는 지원하지 않는다.
- 수취 계좌는 가입 시 등록한 계좌를 서버에서 조회한다. 본인 소유의 `ACTIVE` 입출금 계좌이고 출금계좌로 등록돼 있어야 한다. 이 API에서 수취 계좌를 변경할 수 없다.
- 적용금리·이자 계산 기간·원리금은 서버가 계산한다. 만기 이후 기간의 추가 이자는 지급하지 않는다.
- 현재 만기해지 API는 OTP 토큰을 받지 않는다.

## 2. 계좌비밀번호 인증

`POST /api/v1/accounts/{accountId}/password/verify`

로그인 세션과 CSRF 헤더가 필요하다. 수취 계좌가 아닌 **해지할 계좌 ID**를 경로에 넣는다.

```json
{
  "accountPassword": "1234"
}
```

성공 응답 `data.accountPasswordAuthToken`을 다음 만기해지 요청의 헤더로 전달한다. 토큰은 발급 후 300초 동안 유효한 일회용 값이다. 비밀번호와 토큰을 URL이나 로그에 넣지 않는다.

| 인증 오류 | FE 처리 |
| --- | --- |
| `APW0001` / 400 | 비밀번호 재입력. 응답의 `data.errorCount`, `data.remainingAttempts`로 잔여 횟수 안내 |
| `APW0101` / 403 | 계좌비밀번호 잠금 안내. 반복 입력 중단 |
| `ACC0201` / 404 | 계좌를 찾을 수 없거나 접근할 수 없다는 공통 안내 |

## 3. 만기해지 요청

`POST /api/v1/accounts/{accountId}/maturity-termination`

| 항목 | 필수 | 값 |
| --- | --- | --- |
| 경로 `accountId` | Y | 해지할 상품 계좌의 양수 내부 ID |
| 로그인 세션 쿠키 | Y | 로그인으로 발급받은 세션. 브라우저 요청에 쿠키 포함 |
| `X-XSRF-TOKEN` | Y | 현재 `XSRF-TOKEN` 쿠키 값 |
| `Idempotency-Key` | Y | 해지 요청 1건마다 새 UUID v4 |
| `Account-Password-Auth-Token` | Y | §2에서 해지할 계좌로 발급받은 일회용 토큰 |
| 요청 본문 | 없음 | 고객 ID·수취 계좌·금리·금액을 보내지 않음 |

JavaScript 호출 예시다. `csrfToken`은 현재 CSRF 쿠키에서 읽은 값이고, `accountPasswordAuthToken`은 비밀번호 검증 응답값이다. 두 값은 서로 다른 토큰이다.

```javascript
const idempotencyKey = crypto.randomUUID();

// 응답이 확인되지 않은 재시도에서는 idempotencyKey를 새로 만들지 않는다.
const response = await fetch(`/api/v1/accounts/${accountId}/maturity-termination`, {
  method: "POST",
  credentials: "include",
  headers: {
    "X-XSRF-TOKEN": csrfToken,
    "Idempotency-Key": idempotencyKey,
    "Account-Password-Auth-Token": accountPasswordAuthToken,
  },
});
const result = await response.json();
```

## 4. 성공 응답

성공은 HTTP `200` + `code="0000"`이다. 금액은 모두 소수점 없는 원 단위 정수다. 아래 값은 응답 형태를 보여주는 예시다.

```json
{
  "code": "0000",
  "message": "만기해지가 완료되었습니다.",
  "data": {
    "accountId": 101,
    "withdrawalAccountId": 202,
    "principal": 1000000,
    "grossInterest": 10000,
    "tax": 1540,
    "netInterest": 8460,
    "totalTransferred": 1008460,
    "transactionNumber": "20261022WB0000000001",
    "tradeDate": "2026-10-22",
    "closedAt": "2026-10-22T13:00:00"
  }
}
```

| 필드 | 의미 |
| --- | --- |
| `accountId` | 해지된 예·적금 계좌 내부 ID |
| `withdrawalAccountId` | 원리금을 받은 가입 당시 등록 계좌의 내부 ID |
| `principal` | 이자 지급 후 실제 상품 계좌 잔액에서 세후이자를 뺀 원금 |
| `grossInterest` | 세전이자 |
| `tax` | 원천징수세액 |
| `netInterest` | 세후이자 (`grossInterest - tax`) |
| `totalTransferred` | 실제 지급 원리금 (`principal + netInterest`) |
| `transactionNumber` | MATURITY 원리금 이체 거래번호. 문자열로 취급 |
| `tradeDate` | 원리금 이체의 논리 거래일 (`YYYY-MM-DD`) |
| `closedAt` | 실제 계좌 종료 시각. KST의 오프셋 없는 날짜·시각 문자열 |

`tradeDate`는 서버 영업일 기준이라 `closedAt`의 날짜와 다를 수 있다. 화면에서 두 값을 임의로 같게 보정하지 않는다. `closedAt`을 UTC로 간주해 9시간을 더하지 않는다. 계좌 ID는 계좌번호가 아니므로 계좌번호 표시에는 별도 계좌 조회 결과를 사용한다.

## 5. 멱등 처리와 재시도

- 응답을 받지 못했으면 **같은 고객·같은 계좌·같은 멱등키**로 재시도한다. 처리 중에는 `CMN0301`, 완료된 요청이면 최초 성공 응답을 반환한다. 확인되지 않은 요청에 새 키를 발급해 자동 재전송하지 않는다.
- 성공 응답 재생은 업무 실행 전에 처리하므로 이미 소비된 비밀번호 인증 토큰을 다시 검증·소비하지 않는다. 단, 필수 헤더는 재요청에도 포함해야 한다.
- 멱등 요청 비교에는 계좌 ID를 사용한다. 비밀번호 인증 토큰은 비교 대상이 아니므로 재인증으로 토큰이 바뀌어도 같은 요청의 키를 유지할 수 있다.
- 같은 키를 다른 계좌나 다른 요청에 사용하면 `CMN0302`다. 키를 공유하지 말고 사용자 요청과 연결해 관리한다.
- 업무 오류 응답을 받으면 멱등키 예약은 해제된다. 기본 JDBC 토큰 저장소에서는 업무 롤백 시 토큰 소비도 롤백된다. 토큰 만료 또는 `APW0102`가 발생하면 비밀번호 인증을 다시 수행한다. Redis 저장소에서는 롤백돼도 소비된 토큰이 복구되지 않는다([공통 토큰 정책](../api_conventions.md) §6).
- 멱등 응답의 보관 기간이 지난 요청을 무기한 재생한다고 가정하지 않는다. 성공 여부를 확인할 때 계좌 상태와 거래내역도 조회한다.

## 6. 오류와 화면 처리

일반 업무 오류 응답은 다음 봉투를 사용한다. 오류코드로 분기하고 메시지 문자열에 의존하지 않는다.

```json
{
  "code": "APW0102",
  "message": "계좌비밀번호 인증 토큰이 유효하지 않습니다.",
  "data": null
}
```

| HTTP | 코드 | 의미 / FE 처리 |
| --- | --- | --- |
| 400 | `CMN0001` | 계좌 ID·멱등키 등 입력 형식 확인 |
| 400 | `CMN0002` | 필수 헤더·필수값 누락. 요청 구성 확인 |
| 401 | `CMN0101` | 로그인 필요 또는 세션 만료. 재로그인 안내 |
| 403 | `APW0101` | 계좌비밀번호 잠금 안내 |
| 403 | `APW0102` | 토큰 무효·만료·재사용·고객/계좌 불일치. 해지할 계좌로 재인증 |
| 404 | `ACC0201` | 상품/수취 계좌 접근 불가 또는 수취 계좌 조건 불충족. 계좌 정보 새로고침 |
| 404 | `PRD0203` | 로그인 고객의 해당 계좌 가입 내역 없음 |
| 409 | `ACC0301` | 계좌 상태가 만기해지 조건에 맞지 않음. 상세 새로고침 |
| 409 | `ACC0305` | 만기해지 지원 계좌 유형이 아님 |
| 409 | `ACC0306` | 실제 계약 만기일 미도래. KST 기준 만기일 안내 |
| 409 | `ACC0307` | 종료 시 잔액 0원 조건 불충족. 자동 반복 요청 중단 |
| 409 | `PRD0302` | 이미 이자 지급됨. 계좌 상태·거래내역 확인 |
| 409 | `PRD0303` | 가입 처리 미완료. 상세 새로고침 |
| 409 | `PRD0304` | 지급할 원리금이 0원. 자동 반복 요청 중단 |
| 409 | `PRD0305` | 자동 재예치 미지원 안내 |
| 409 | `CMN0301` | 같은 멱등키 요청 처리 중. 키를 유지해 이후 재확인 |
| 409 | `CMN0302` | 다른 요청에 사용한 멱등키. 요청과 키의 연결 확인 |
| 5xx | 공통 서버 오류 | 원리금 지급 성공으로 표시하지 않고 결과 재확인 안내 |

CSRF 헤더 누락·불일치도 보안 단계에서 HTTP `403`으로 거부된다. 모든 `403`을 비밀번호 오류로 처리하지 않는다. 업무 코드와 구분해 현재 세션·CSRF 쿠키를 확인한다. 네트워크 단절이나 5xx만으로 미처리를 확정하지 않는다.

## 7. FE 확인 항목

- 정상 요청의 HTTP 200·`0000` 및 원금·세전이자·세금·세후이자·총 지급액 표시.
- 성공 후 상품 계좌 `CLOSED`·잔액 0원, 수취 계좌 잔액과 거래내역 새로고침.
- 계약 만기 전 요청, RENEW, 수취 계좌 조건 불충족, 비밀번호 잠금·토큰 만료 안내.
- 버튼 중복 클릭 방지 및 응답 유실 시 같은 키 재시도. 성공 응답 재생으로 결과가 바뀌지 않는지 확인.
- 세션 만료와 CSRF 실패를 비밀번호 인증 실패와 구분.
