# PH-08 무차별 로그인 주입 — 계정 열거 차단 측정

> 운영과 같은 기존 EC2에 가입 계정과 없는 아이디로 틀린 비밀번호를 6회씩 보내, 응답으로 둘을 구분할 수 있는지 쟀다(#900, 2026-11-09 · 11/10).
> 회차마다 로그인 요청 12,100건(아이디 2,000개 × 6회 + 대조군 100건)에서 **응답 순서 100% 동일 · 5회째 차단 100% · 오탐 0%**이고, 잠긴 뒤 응답 시간 차이는 수정 후 **중앙값 +2.06 · +2.05ms → −0.33ms**(3회 중앙값)로 줄었다.

## 2. 경로별 응답 시간 차이 (없는 아이디 − 가입 계정, ms)

공격자가 같은 시간대에 두 쪽을 비교하므로 **같은 회차 안의 차이**를 본다. 양수면 없는 아이디 쪽이 느리다.

|---|---|---|---|---|---|

- **잠긴 뒤 차이는 수정 전 두 회차에서 같은 크기로 재현됐다.** 잠긴 가입 계정은 고객 조회 후 바로 응답하고, 잠긴 없는 아이디는 아이디 HMAC 계산과 실패 횟수 조회가 더 있었다. 잠긴 아이디는 더 잠기지 않아 같은 아이디로 반복 요청해 평균을 낼 수 있으므로 고쳤다.
- **수정(PR #964):** 잠긴 가입 계정도 같은 실패 횟수 조회를 거친다. 가입 계정 쪽 중앙값이 15.93 · 13.21 → 17.14~18.74ms로 올라 없는 아이디 쪽과 같은 수준이 됐다.
- 수정 후 중앙값 차이는 −0.33 · −0.33 · −0.19ms로 수정 전의 1/6 이하이고, 같은 경로 안의 응답 시간 편차(p95 − 중앙값, 8.0~18.5ms)보다 훨씬 작다. p95 차이는 −1.60 · −2.19 · −0.45ms로 회차 간 편차가 크다.
- 틀린 비밀번호 · 잠기는 순간은 두 쪽 모두 BCrypt가 돌아 200ms대이고, 차이의 부호가 회차마다 바뀌고 응답 시간 편차(p95 − 중앙값, 58~102ms) 안이다.

## 4. 한계

- **남은 차이는 방향이 같다.** 수정 후 잠긴 뒤 중앙값 차이가 세 회차 모두 음수(−0.33 · −0.33 · −0.19ms, 가입 계정 쪽이 조금 느림)다. 회차당 대상 1,000개 비교로는 응답 시간 편차보다 작지만, 한 아이디에 같은 요청을 아주 많이 보내 평균을 내면 드러날 수 있다. 잠긴 아이디는 더 잠기지 않으므로 이 반복은 IP 단위 요청량 제한(P2 PH-58 WAF, [D-07](README.md#d-07--919--p1p2))이 막아야 하는 영역이다.
