### 1-1. 사람별 UAT 고객

회원가입은 기존 은행 Mock 원장 고객만 할 수 있고 재가입이 막혀 있어(ATH0303), UAT 전용 원장 고객을 PR #797로 추가했다.
계좌는 모두 잔액 0원이다. 가입 시 계좌가 원장 기록 없이 잔액째 복사되므로(#512), 잔액이 있으면 COB 대사가 불일치로 잡는다.

| 실행자 | 성명 | 생년월일 | 계좌번호 | 계좌비밀번호 | 아이디(권장) |
|---|---|---|---|---|---|
| P1 | 박서연 | 950101 | 110900000001 | 1234 | `uat1104p1` |
| P2 | 최민준 | 950202 | 110900000002 | 1234 | `uat1104p2` |
| P3 | 정하은 | 950303 | 110900000003 | 1234 | `uat1104p3` |
| P4 | 강도윤 | 950404 | 110900000004 | 1234 | `uat1104p4` |
| P5 | 윤지우 | 950505 | 110900000005 | 1234 | `uat1104p5` |
| P6 | 임서준 | 950606 | 110900000006 | 1234 | `uat1104p6` |

- 아이디는 영문 소문자로 시작하는 6~16자(`^[a-z][a-z0-9]{5,15}$`)다. 이메일은 `<아이디>@example.com`을 쓴다.
- 로그인 비밀번호는 각자 정하고 문서와 이슈에 적지 않는다.
- **기존 Mock 고객 홍길동(110123456789, 110987654321)과 김영희(110555666777)로는 가입하지 않는다.** 잔액이 있어 가입하면 대사 불일치 3건이 생긴다.
- 원장 고객 1명은 한 번만 가입할 수 있다. 가입이 중간에 실패해도 다른 사람의 고객으로 다시 시도하지 않고 P3에게 알린다.

## 2. 판정과 통과율

### 2-1. 판정

| 판정 | 기준 |
|---|---|
| 통과 | 기대 결과를 모두 충족했다 |
| 실패 | 기대 결과 중 하나라도 충족하지 못했다 |
| 차단 | 앞 단계 실패나 환경 문제로 이 시나리오를 시작하지 못했다 |
| 범위 밖 | 조건부 항목이 릴리스 3에 없어 실행하지 않았다 |

- 기대 결과와 무관한 문구 오류나 레이아웃 문제는 판정에 반영하지 않고 경미 결함으로만 보고한다.
- 실행 건은 "시나리오 ID × 실행자"로 센다. U-C01을 6명이 실행하면 6건이다.
- 같은 결함을 여러 사람이 만나면 이슈는 하나만 만들고, 나머지는 시트에 그 이슈 번호를 적는다.

### 2-2. 지표

```
통과율 = 통과 ÷ (통과 + 실패)
실행률 = (통과 + 실패) ÷ (계획 건수 − 범위 밖)
```

- 차단은 통과율 분모에서 빼고, 실행률로 드러낸다. 통과율을 인용할 때는 실행률을 함께 적는다.
- 결함 심각도(§4-2)는 지표에 섞지 않고 결함 목록에 따로 적는다.

## 4. 결함 보고

### 4-1. 어디에 올리나

| 결함 위치 | 레포 | 양식 |
|---|---|---|
| 서버 응답, 금액, 원장, 권한 | corebank-server | `.github/ISSUE_TEMPLATE/bug.md` |
| 화면 표시, 입력, 이동 | corebank-fe | 서버 bug 양식과 같은 구성, `bug` 라벨 |
| 판단이 어려움 | corebank-server | P3가 분류해 옮긴다 |

제목은 각 레포 규약을 따르고 끝에 시나리오 ID를 붙인다. 예: `[fix/transfer] 타행이체 결과 화면에 수수료 미표시 (UAT U-C05)`.

### 4-2. 필수 기재

"현상" 절 맨 앞에 아래 다섯 줄을 쓴다.

```
- 시나리오: U-C05
- 실행 계정: uat1104p2
- 발생 시각: 2026-11-04 14:12 (KST)
- Correlation ID: (개발자도구 Network 탭의 요청 헤더 X-Correlation-Id)
- 심각도: 차단 / 주요 / 경미
```

| 심각도 | 기준 |
|---|---|
| 차단 | 흐름을 더 진행할 수 없다. 금액이나 잔액이 틀리다. 다른 고객 정보나 내부 정보가 노출된다 |
| 주요 | 기대 결과를 충족하지 못하지만 우회해서 진행할 수 있다 |
| 경미 | 문구, 레이아웃처럼 기능 결과에는 영향이 없다 |

### 4-3. 하지 않는 것

- 운영 DB를 직접 조회하거나 고치지 않는다. 확인은 화면과 API로만 한다.
- 이슈 본문에 로그인 비밀번호, 계좌비밀번호, OTP 번호를 적지 않는다.
- S4는 새 BE 코드 금지([README.md](README.md) §2)라 결함은 원칙적으로 고치지 않고 리포트에 기록한다. 차단 결함은 P3가 당일 팀에 공유하고 대응을 정한다.
