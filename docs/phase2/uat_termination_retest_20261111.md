# UAT 만기해지·중도해지 재검증 결과 (2026-11-11)

> 이 문서는 2026-11-05 PH-09 UAT에서 실패한 U-C09·U-C10을 수정 이후 다시 실행한 결과다. 최초 UAT 실패 기록과 집계는 변경하지 않는다.

| 검증 환경 | 운영 AWS 3-Tier, Swagger UI/API 및 고객 상품가입 화면 |

| 재검증 결과 | **2건 모두 통과** (각 시나리오의 API 응답·계좌 상태·수취 계좌 거래내역 확인) |

## 1. 배경과 검증 범위

2026-11-05 UAT에서 다음 두 건이 실패했다.

| 시나리오 | 최초 실패 | 수정 작업 |
|---|---|---|
| U-C09 만기해지 | 계좌 비밀번호 인증 후 만기해지 요청에서 `HTTP 409 / CMN0303` 발생. `AccountJpaEntity` 버전 충돌로 해지 실패 | [서버 #911](https://github.com/corebank-tech/corebank-server/issues/911), [PR #935](https://github.com/corebank-tech/corebank-server/pull/935) |
| U-C10 중도해지 | 상품가입 과정에서 신규 상품 계좌 비밀번호가 무작위 생성돼 고객이 알 수 없음. `password/verify`에서 `HTTP 400 / APW0001` 발생, 해지 API까지 진행하지 못함 | [FE #211](https://github.com/corebank-tech/corebank-fe/issues/211), [FE PR #215](https://github.com/corebank-tech/corebank-fe/pull/215) |

이번 검증은 수정 후 **정상 흐름에서 실제 원리금 지급과 계좌 종료가 완료되는지** 확인한다. 해지 호출은 Swagger UI/API로 실행했다. 상품가입은 고객 화면에서 진행했으며, 해지 자체의 FE 화면 통합 시험은 아니다.

## 2. 실행 환경 및 사전 조건

- 운영 3-Tier에서 U-C09·U-C10 재검증을 진행했다.
- U-C10 실행 전 P5가 두 WAS(끝자리 `42`, `10`)에서 `APP_SUBSCRIPTION_EARLYTERMINATION_ENABLED=true`로 컨테이너를 재생성했다. 2026-11-11 13:49 기준 두 서버의 ALB 헬스체크는 `healthy`였다.
- 중도해지 API가 Swagger UI에 노출된 상태에서 U-C10을 실행했다.
- U-C09는 기존 만기 상품 계좌 `100000002`를 사용했다.
- U-C10은 11/05에 비밀번호 인증에 실패했던 계좌 `100150098`을 재사용하지 않고, **11/11 신규 가입한 상품 계좌 `100150102`**를 사용했다. 신규 계좌의 비밀번호 인증 및 해지 요청은 성공했다.
- FE 수정 PR의 운영 배포 커밋·빌드 식별자는 별도로 확인하지 않았다. 따라서 API 성공만으로 특정 FE 빌드가 배포됐다고 단정하지 않는다.

## 3. U-C09 만기해지 재검증

### 3-1. 실행 내용

1. 시드 고객으로 로그인하고 상품 계좌 `100000002`의 해지 가능 상태를 확인했다.
2. `POST /api/v1/accounts/100000002/password/verify`로 상품 계좌 비밀번호 인증 토큰을 발급받았다.
3. 신규 UUID 멱등키와 인증 토큰을 사용해 `POST /api/v1/accounts/100000002/maturity-termination`을 호출했다.
4. 상품 계좌 상태·잔액과 원리금 수취 계좌 `100000001`의 거래내역을 확인했다.

### 3-2. API 응답과 금액 대조

| 항목 | 결과 |
|---|---:|
| 응답 코드 | `0000` — 만기해지 완료 |
| 상품 계좌 ID | `100000002` |
| 수취 계좌 ID | `100000001` |
| 원금 (`principal`) | 500,000원 |
| 세전이자 (`grossInterest`) | 1,068원 |
| 세금 (`tax`) | 150원 |
| 세후이자 (`netInterest`) | 918원 |
| 총 지급액 (`totalTransferred`) | **500,918원** |
| 거래번호 | `20261111WB0000000002` |
| 거래일 | `2026-11-11` |
| 해지 처리 시각 | `2026-11-11 11:46:59` |

금액 대조:

- `1,068 - 150 = 918`원 (세후이자)
- `500,000 + 918 = 500,918`원 (총 지급액)

### 3-3. 계좌·원장 확인

- 상품 계좌 `100000002`: 실행자가 `CLOSED`, 잔액 0원을 확인했다.
- 수취 계좌 `100000001`: 다음 입금 거래를 확인했다.

| 필드 | 값 |
|---|---|
| `ledgerEntryId` | `106099561` |
| `transactionNumber` | `20261111WB0000000002` |
| `transactionType` | `MATURITY` |
| `depositAmount` | 500,918원 |
| `balanceAfter` | 9,450,918원 |
| `reversed` | `false` |
| `occurredAt` | `2026-11-11T11:46:59.012143` |

**판정: 통과.** 기존 `CMN0303`가 이번 요청에서 재발하지 않았고, 반환된 지급액과 수취 계좌 입금액·거래번호가 일치한다.

## 4. U-C10 중도해지 재검증

### 4-1. 실행 내용

1. 고객 화면에서 기본 정기예금에 100,000원, 가입기간 6개월로 신규 가입했다.
2. 신규 상품 계좌 ID `100150102`를 확인하고 상품 계좌 비밀번호로 `POST /api/v1/accounts/100150102/password/verify` 인증을 완료했다.
3. 신규 UUID 멱등키와 인증 토큰을 사용해 `POST /api/v1/accounts/100150102/early-termination`을 호출했다.
4. 상품 계좌를 다시 조회하고 원리금 수취 계좌 `100000001`의 입금 거래를 확인했다.

### 4-2. API 응답과 금액 대조

| 항목 | 결과 |
|---|---:|
| 응답 코드 | `0000` — 중도해지 완료 |
| 상품 계좌 ID | `100150102` |
| 수취 계좌 ID | `100000001` |
| 원금 (`principal`) | 100,000원 |
| 세전이자 (`grossInterest`) | 0원 |
| 세금 (`tax`) | 0원 |
| 세후이자 (`netInterest`) | 0원 |
| 총 지급액 (`totalTransferred`) | **100,000원** |
| 거래번호 | `20261111WB0000000201` |
| 거래일 | `2026-11-11` |
| 해지 처리 시각 | `2026-11-11 14:20:37` |

금액 대조:

- `0 - 0 = 0`원 (세후이자)

- 가입일과 해지일이 같아 경과일 0일의 기대 결과(이자 0원)와 일치한다.

## 5. 수취 계좌 거래 흐름 정합성

수취 계좌 `100000001`의 11/11 거래내역에서 아래 순서를 확인했다.

| 시각(KST) | 거래 유형 | 거래번호 | 입출금액 | 거래후잔액 |
|---|---|---|---:|---:|
| 11:46:59 | `MATURITY` | `20261111WB0000000002` | +500,918원 | 9,450,918원 |
| 11:55:35 | `PRODUCT_SUBSCRIPTION` | `20261111WB0000000101` | -100,000원 | 9,350,918원 |
| 14:20:37 | `TERMINATION` | `20261111WB0000000201` | +100,000원 | 9,450,918원 |

- 만기해지 이후 상품가입 출금: `9,450,918 - 100,000 = 9,350,918`원
- 중도해지 원금 반환 이후: `9,350,918 + 100,000 = 9,450,918`원
- 세 거래 모두 입출금액과 거래후잔액의 흐름이 일치한다. 원장 거래들의 `reversed` 값은 모두 `false`다.

## 6. 최종 결과와 한계

| 시나리오 | 11/05 최초 UAT | 11/11 재검증 | 확인 근거 |
|---|---|---|---|
| U-C09 만기해지 | 실패 (`409 / CMN0303`) | **통과** | 지급 결과, `CLOSED`·잔액 0원, `MATURITY` 입금 내역 |
| U-C10 중도해지 | 실패 (인증 `400 / APW0001`) | **통과** | 신규 가입 계좌 비밀번호 인증, 지급 결과, `CLOSED`·세 잔액 0원, `TERMINATION` 입금 내역 |

이번 검증으로 **해지 정상 흐름 2건**에서 금액 산술, 원장 입금, 최종 계좌 종료 상태가 기대 결과와 일치했음을 확인했다. 다만 다음 사항은 이 결과로 입증하지 않는다.

- 만기이자 1,068원의 **독립적인 금리·일수 계산 검증** 및 중도해지 구간별 금리 경계값 검증
- GL 전표의 차변·대변 직접 대조, COB 사후 대사 및 동시성·멱등 재시도 검증
- 15만 계좌 원리금 전수 대조(PH-19b) 또는 전체 생명주기 E2E 완료
- FE의 해지 화면까지 포함한 브라우저 E2E, 실제 운영 FE 배포 빌드 식별
- 운영 서버 교체 후 중도해지 스위치 설정의 영속성 및 상시 활성화 적합성

최초 UAT의 **48건 중 46건 통과·2건 실패(95.8%)** 집계는 당시 결과로 유지한다. 이 문서는 수정 후 **2건 재검증 통과**를 추가로 기록하며, 최초 UAT 통과율을 소급 변경하지 않는다.

## 7. 후속 조치

- **P5·P4:** 최종 발표 시연 범위를 확인한 후 중도해지 스위치 상시 유지 여부를 결정한다. 현재 두 WAS에서 수동 적용한 환경변수는 서버 교체 시 사라질 수 있으므로 배포·교체 설정에 반영할지 별도 결정이 필요하다.
- **P2 / PH-19b:** 이 문서를 해지 정상 흐름 검증 근거로 활용하되, 15만 계좌 원리금 전수 대조와 독립 계산 대조는 별도 진행한다.

> 인증 토큰, 계좌 비밀번호, 세션 쿠키, 멱등키 원문은 이 문서에 기록하지 않는다.
