> WAS를 거친 확인과 측정은 §3에 있다(#818, 2026-11-06).

### WAS 응답 제한 시간(`app.info-api.read-timeout`, 현재 5초) 판단

- 관측한 가장 느린 값은 첫 호출 2.33초로 제한의 약 47%이고, 반복 측정은 0.66초 이하다. 지금은 **5초를 유지한다.**
- 가입 요약 시간은 한 달의 이벤트 수에 따라 늘어난다. 이벤트가 몇 배로 늘면 5초에 가까워질 수 있다(단순 비례 추정이며 확인한 값이 아니다).
- 이 절은 VM 직접 호출 기준이다. WAS와 VPN 구간을 포함한 값과 `read-timeout` 재판단은 §3.3에 있고 결론은 5초 유지다. 동시 요청 영향은 아직 측정하지 않았다(§4).

## 3. WAS를 거친 확인과 응답 시간 (2026-11-06, #818)

### 3.1 `asOf` 확인

- P3가 UAT 관리자 시나리오(U-A02~A04)와는 따로 정보계 대시보드 화면에서 총 예수금 잔액, 11월 가입·해지가 **2026-11-04 마감** 기준으로 나오는 것을 확인했고, `deposit-balances`가 200으로 응답해 WAS 경유로 `asOf`까지 정상이라고 알려 왔다(11/6, 확인 시각은 모른다).
- 마트 `mart_load_batch`(11/6 조회): 11/4분이 11/5 03:31:13에, 11/5분이 11/6 03:31:24에 `COMPLETED`다. P3가 본 시점이 11/5 03:31~11/6 03:31 사이였다면 그때의 마지막 적재일이 11/4라서 화면과 맞는다.
- 측정 요청은 응답 본문을 버렸다. 그래서 측정 뒤에 같은 WAS 서버에서 관리자 로그인 세션으로 두 API의 `asOf`를 직접 읽었다(11/6 오후). 잔액 추이(`from=2026-11-01&to=2026-11-05`)와 가입 요약(`month=2026-11`) 모두 `"asOf":"2026-11-05"`로, 마트의 마지막 적재일(11/5분이 11/6 03:31:24 `COMPLETED`)과 같다.

### 3.3 해석과 `read-timeout` 판단

- **VPN 구간이 더한 시간(§2 VM 직접 호출과 경로 A 비교):** 잔액 추이 중앙값이 0.011~0.014초에서 0.025초로 약 0.01초, 가입 요약이 약 0.02~0.03초 늘었다. 서버 처리 시간이 대부분이고 VPN 영향은 작다. 잔액 추이는 기간이 달라(10/29까지 대 11/5까지) 이 비교가 근사값이다.
- **ALB와 WAS 앱 처리가 더한 시간(경로 A와 B 비교):** 중앙값이 약 0.08초 늘었다. 경로 B는 요청마다 새 TLS 연결을 맺는 비용이 들어 있어서 연결을 재사용하는 브라우저의 체감은 이보다 덜할 가능성이 있다(일반적인 동작에 따른 해석이며 확인하지 않았다).
- **`read-timeout`(WAS가 정보계 API를 기다리는 시간)은 5초를 유지한다.** 이 제한에 걸리는 구간(경로 A)의 관측 최대는 0.961초로 5초의 약 19%다. 10/30의 첫 호출 2.33초(약 47%)가 여전히 가장 큰 관측값이다.
- 가입 요약 시간은 한 달의 이벤트 수에 따라 늘어난다는 §2의 추정은 그대로다(단순 비례 추정이며 확인한 값이 아니다).
- 경로 B의 첫 묶음(잔액 추이 100회)의 최대 0.619초는 한 번 튄 값이다. 같은 조건의 p99는 0.210초다.

## 4. 아직 하지 않은 것

- 동시 요청을 넣은 측정과 이벤트 수가 늘었을 때의 재측정.
- 서버 두 대를 모두 잰 값과 사용자 브라우저에서 잰 값.
- 운영 거래가 쌓인 뒤의 `asOf` 지연(적재 시각 03:30과 관리자 화면 조회 시각의 관계).

## 5. 재현 방법

비밀(`INFO_API_SECRET`)은 VM의 `/etc/info-api/info-api.env`에만 있다. 변수에 담아 설정 파일 방식으로 넘겨 명령줄과 프로세스 목록에 남기지 않는다.

```bash
S=$(sudo grep '^INFO_API_SECRET=' /etc/info-api/info-api.env | cut -d= -f2-)
pt(){ for i in $(seq $2); do curl -s -o /dev/null -w '%{time_total}\n' --config <(printf 'header = "X-Info-Api-Secret: %s"\n' "$S") "$1"; done | sort -n | awk '{a[NR]=$1} END{printf "n=%d p50=%.3f p95=%.3f p99=%.3f max=%.3f\n",NR,a[int(NR*0.5)],a[int(NR*0.95)],a[int(NR*0.99)],a[NR]}'; }
pt "http://192.168.0.211:8081/info/deposit-balances?from=2026-10-01&to=2026-10-29" 300
pt "http://192.168.0.211:8081/info/product-subscriptions?month=2026-09" 100
```

WAS를 거친 측정(§3)은 3-Tier WAS 서버에서 `bash`로 바꾼 뒤 한다. 정보계 API 주소와 비밀은 앱 컨테이너의 환경변수 `APP_INFO_API_BASE_URL`·`APP_INFO_API_SECRET`에서 꺼내 변수에 담고, 같은 `pt` 함수를 `"$B/info/..."` 주소로 부른다(경로 A). 경로 B는 관리자 아이디·비밀번호를 `read -s`로 입력받아 `POST /api/v1/admin/auth/login`에 표준입력으로 넘기고, 받은 쿠키 파일(`curl -c`)로 `GET /api/v1/admin/info/...`를 부른다. 비밀번호와 쿠키는 명령줄·문서·채팅에 남기지 않고, 끝나면 쿠키 파일을 지운다.
