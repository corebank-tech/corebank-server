# PH-77 ④ 정보계 API 실제 값 확인과 응답 시간 측정

> 마트에 적재한 뒤 정보계 API가 실제 값으로 응답하는지 확인하고 응답 시간을 기록한다(#803).
> WAS를 거친 측정은 11/3 `main` 릴리스 뒤에 같은 문서에 추가한다.

## 1. 실제 값 확인 (2026-10-30, VM에서 API 직접 호출)

| 확인 | 결과 |
| --- | --- |
| `asOf` | `2026-10-29`. 마트의 마지막 적재일(`mart_load_batch`의 마지막 `COMPLETED`)과 같다 |
| 잔액 추이 10/20~10/29 | 영업일 8개 항목(10/20~10/23, 10/26~10/29). 합계 1,060,000,760,000 (ETL 적재 로그의 `total`과 일치) |
| 가입 요약 2026-09 | 가입 86,145건 = 기본 정기예금 41,145 + 코어 정기적금 43,000 + 코어 단기예금 2,000, 해지 0 |
| 가입 요약 2026-10 | 가입 13,855건 = 기본 정기예금 6,855 + 코어 정기적금 7,000, 해지 0 |
| 이벤트 합계 | 9월 + 10월 = 100,000건. 마트의 이벤트 행 수 100,000과 같다 |
| 개인정보 | 응답 필드는 날짜·합계·상품 ID·코드·이름·그룹·건수뿐이고 계좌번호·고객 정보는 없다 |

- 잔액 합계가 날짜마다 같은 것은 시드 이체가 계좌 간 이동뿐이라 합계가 변하지 않기 때문이다([ph76_etl_first_load.md](ph76_etl_first_load.md) §2).
- 해지 0과 10/7 이후 가입 0은 팀이 넣은 시드와 새 가입이 없는 상태의 결과다. 실제 운영 값이 아니다.

## 2. 응답 시간

### 측정 조건

| 항목 | 값 |
| --- | --- |
| 측정 일시 | 2026-10-30 약 10:50 KST |
| 호출 위치 | VM 안에서 `http://192.168.0.211:8081`을 직접 호출한다. WAS와 VPN 구간은 포함되지 않는다 |
| 방식 | 같은 요청을 순차로 반복했다(단일 클라이언트, 동시 요청 없음). 응답 본문은 버리고 `curl`의 `time_total`만 모았다 |
| 마트 | 9/1~10/29 39일 적재, 이벤트 100,000건 |
| 같은 VM의 다른 부하 | 레플리카(복제 중), 마트, 정보계 API 컨테이너. ETL은 돌지 않았다(타이머는 03:30) |

### 결과 (초)

| 경로와 조건 | 횟수 | p50 | p95 | p99 | 최대 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 잔액 추이 `from=2026-10-01&to=2026-10-29` | 300 | 0.014 | 0.024 | 0.031 | 0.036 |
| 잔액 추이 `from=2026-09-01&to=2026-10-29` | 300 | 0.011 | 0.016 | 0.019 | 0.034 |
| 가입 요약 `month=2026-09` (이벤트 86,145건) | 100 | 0.617 | 0.640 | 0.650 | 0.655 |
| 가입 요약 `month=2026-10` (이벤트 13,855건) | 100 | 0.393 | 0.404 | 0.407 | 0.415 |

- 처음 한 번 호출한 값은 가입 요약 2026-09가 2.33초, 2026-10이 0.44초, 잔액 추이가 0.048초였다. 캐시가 비어 있던 첫 호출이다.
- 가입 요약이 이벤트 서브쿼리를 포함해 가장 느리고, 한 달의 이벤트 수에 따라 시간이 늘어난다(0.39초 → 0.62초). 잔액 추이는 기간이 길어도 영향이 작다.
- p99는 100~300회 측정이라 가장 느린 몇 번에 가깝다. 참고값이다.

### WAS 응답 제한 시간(`app.info-api.read-timeout`, 현재 5초) 판단

- 관측한 가장 느린 값은 첫 호출 2.33초로 제한의 약 47%이고, 반복 측정은 0.66초 이하다. 지금은 **5초를 유지한다.**
- 가입 요약 시간은 한 달의 이벤트 수에 따라 늘어난다. 이벤트가 몇 배로 늘면 5초에 가까워질 수 있다(단순 비례 추정이며 확인한 값이 아니다).
- WAS와 VPN 구간의 시간과 동시 요청 영향은 측정하지 않았다. WAS를 거친 측정은 §3에서 한다.

## 3. 아직 하지 않은 것

- WAS를 거친 확인(#818): 관리자 화면 요청이 WAS와 VPN을 거쳐 실제 마트 값으로 응답하고 `asOf`가 맞는지, 그 구간 포함 p95·p99. #804(PR #805)와 11/3 `main` 릴리스 뒤에 한다. 이 확인 뒤에 `read-timeout`을 다시 판단한다.
- 동시 요청을 넣은 측정과 이벤트 수가 늘었을 때의 재측정.
- 운영 거래가 쌓인 뒤의 `asOf` 지연(적재 시각 03:30과 관리자 화면 조회 시각의 관계).

## 4. 재현 방법

비밀(`INFO_API_SECRET`)은 VM의 `/etc/info-api/info-api.env`에만 있다. 변수에 담아 설정 파일 방식으로 넘겨 명령줄과 프로세스 목록에 남기지 않는다.

```bash
S=$(sudo grep '^INFO_API_SECRET=' /etc/info-api/info-api.env | cut -d= -f2-)
pt(){ for i in $(seq $2); do curl -s -o /dev/null -w '%{time_total}\n' --config <(printf 'header = "X-Info-Api-Secret: %s"\n' "$S") "$1"; done | sort -n | awk '{a[NR]=$1} END{printf "n=%d p50=%.3f p95=%.3f p99=%.3f max=%.3f\n",NR,a[int(NR*0.5)],a[int(NR*0.95)],a[int(NR*0.99)],a[NR]}'; }
pt "http://192.168.0.211:8081/info/deposit-balances?from=2026-10-01&to=2026-10-29" 300
pt "http://192.168.0.211:8081/info/product-subscriptions?month=2026-09" 100
```
