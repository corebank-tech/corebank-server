# 모의 대외기관 서버 (PH-33-①)

> **정본이다.** 모의 대외기관(타행)을 띄우는 방법, 응답 규칙, 장애 스위치를 이 문서에 적는다.
> 전문 모양은 [fixed_length_message_spec.md](fixed_length_message_spec.md)(PH-31), 태스크 범위는 [tasks.md](tasks.md) §PH-33이다.
>
> **대상**: P4 PH-33-② · PH-36 개발, 온프레미스 VM에 서버를 띄우는 P5

---

## 1. 무엇인가

우리 은행이 타행 이체 전문을 보내는 **가짜 상대 은행**이다. 은행 앱과 다른 프로세스, 다른 실행 파일로 돈다.

```
[WAS 은행 앱] --TCP 전문 124바이트--> [모의 대외기관 :9300]
                                        └ 장애 스위치 HTTP :9301 (curl·테스트가 부른다)
```

- 코드는 같은 저장소의 `src/mockExternal/java`(`com.shinhan.mockexternal`)에 있다. 우리 은행 코드가 아니라 상대 기관이라 `com.shinhan.corebank` 밖에 둔다.
- 전문 변환기 `transfer.adapter.out.external`만 은행 앱과 같이 쓴다. 그래서 양쪽 전문 모양이 어긋날 수 없다.
- Spring·DB 없이 JDK만으로 돈다. 운영 jar(`bootJar`)에는 들어가지 않는다.
- 브라우저가 부르지 않으므로 CORS와 무관하다.

## 2. 띄우기

| 방법 | 명령 |
|---|---|
| 로컬 개발 | `./gradlew runMockExternal` |
| 실행 파일 만들기 | `./gradlew mockExternalJar` → `build/mock-external/mock-external.jar` (약 30KB) |
| 실행 파일로 띄우기 | `java -jar mock-external.jar --bind=0.0.0.0 --port=9300 --admin-port=9301` |

| 인자 | 기본값 | 뜻 |
|---|---|---|
| `--bind` | `127.0.0.1` | 받을 주소. 다른 서버에서 들어오게 하려면 VM 사설 IP나 `0.0.0.0` |
| `--port` | `9300` | 전문 TCP 포트 |
| `--admin-port` | `9301` | 장애 스위치 HTTP 포트 |

- 런타임은 **JDK 21**이다. 최소 JRE(jlink)를 쓰면 `jdk.charsets`(MS949)와 `jdk.httpserver` 모듈이 있어야 한다. WAS 기본 이미지 `eclipse-temurin:21-jre-alpine`에는 둘 다 들어 있고, 이 이미지 컨테이너에서 띄워 전문 `0000` 응답까지 확인했다.
- 로그 시각은 JVM 시간대를 따른다. 컨테이너 기본값은 UTC이므로 WAS처럼 `-Duser.timezone=Asia/Seoul`을 준다. 전문의 전송일시는 이 설정과 무관하게 KST다.
- 살아 있는지는 `curl http://<주소>:9301/health`가 `OK`를 돌려주는지로 본다.
- 로그는 표준 출력이다. 한 줄에 `거래코드 일련번호 → 응답코드 (장애 모드)`를 남긴다.

## 3. 응답 규칙

**이체(`TRF001`)** — 결과는 수취 계좌번호 앞 4자리로 정한다. 호출하는 쪽이 원하는 응답을 골라 받게 하려는 것이다.

| 계좌번호 | 응답 | 장부에 남기나 |
|---|---|---|
| `1001`로 시작 | `1001` 수취 계좌 없음 | 남긴다 |
| `1002`로 시작 | `1002` 수취 계좌 거래 불가 | 남긴다 |
| `9999`로 시작 | `9999` 시스템 오류로 처리 못 함 | **남기지 않는다** — 처리하지 못했으므로 |
| 그 밖 | `0000` 정상, 예금주 `김민수` | 남긴다 |
| 장부에 이미 있는 일련번호 | `2001` 중복 — 재처리하지 않는다 | — |

**조회거래(`INQ001`)** — 장부에 원거래가 있으면 그 결과(`0000`·`1001`·`1002`)를, 없으면 `3001` 원거래 미수신을 돌려준다.

**형식 오류** — 규격에 맞지 않는 전문에는 `1003`으로 답하고 장부에 남기지 않는다. 응답은 받는 쪽이 읽을 수 있게 만든다. 깨진 칸은 돌려주지 않고 일련번호처럼 살릴 수 있는 칸만 싣는다.

- 장부는 메모리에만 있다. **서버를 다시 띄우면 비워진다.**
- 조회거래는 일련번호로만 찾는다. 계좌·금액이 원거래와 같은지는 맞춰 보지 않는다.

## 4. 장애 스위치

```bash
curl -X POST 'http://<주소>:9301/faults?mode=DELAY&delayMs=3000'  # 3초 늦게 응답
curl -X POST 'http://<주소>:9301/faults?mode=NO_RESPONSE'         # 응답하지 않음
curl -X POST 'http://<주소>:9301/faults?mode=DUPLICATE'           # 같은 응답을 두 번
curl -X POST 'http://<주소>:9301/faults?mode=NONE'                # 정상으로 되돌림
curl 'http://<주소>:9301/faults'                                  # 지금 모드 보기
```

- **세 장애 모두 요청은 정상 처리해 장부에 남긴다.** 상대 기관은 처리했는데 응답만 잃거나, 늦거나, 겹쳐 오는 상황을 재현하려는 것이다. 무응답 뒤 스위치를 끄고 조회거래를 보내면 `0000`이 돌아온다.
- 무응답이면 연결을 끊지 않고 상대가 끊을 때까지 잡고 있다. 기다리는 시간(TIMEOUT 기준)은 보내는 쪽이 정한다(PH-33-②).
- 스위치는 서버 전체에 걸린다. 조회거래에도 똑같이 적용되므로, "무응답 → 조회" 흐름은 조회 전에 `NONE`으로 되돌린다.
- 알 수 없는 `mode`는 `400`으로 거부하고 스위치를 바꾸지 않는다.

## 5. P5에 넘기는 실행 계약

온프레미스 대외·모니터링 VM([README.md D-25](README.md#d-25--927--리드-제안팀-회의-확인-대기), [PH-100](tasks.md#ph-100-하이브리드-연결-①-온프레미스-vm-s2--②-vpn-연결-s3))에 띄울 때 필요한 것은 아래가 전부다. 코드를 볼 필요는 없다.

| 항목 | 값 |
|---|---|
| 실행 파일 | `mock-external.jar` |
| 런타임 | JDK 21 (§2 모듈 주의) |
| 실행 | `java -jar mock-external.jar --bind=<VM 사설 IP> --port=9300 --admin-port=9301` |
| 열 포트 | 9300 전문 TCP, 9301 장애 스위치 HTTP. **둘 다 VPN 안에서만** 닿게 한다. 온프레미스의 인터넷 공개 포트는 Nginx 443 하나다 |
| 상태 확인 | `GET :9301/health` → `200 OK` |
| 상태 보존 | 없음. 다시 띄우면 장부가 비워진다 |

**배포 단계 (P5 확인 필요)**

모의 대외기관이 어디에 있든 WAS가 아는 것은 접속 주소 하나다. 그래서 **이미지 하나를 만들고, 위치는 WAS 설정값으로만 바꾼다.** WAS 쪽 주소·포트·대기 시간은 PH-33-② 송신 어댑터가 환경변수로 받는다.

| 단계 | 시기 | 모의 대외기관 위치 | 할 일 |
|---|---|---|---|
| A | 지금 ~ PH-33-② 송신 개발 전 | 배포하지 않는다. 로컬에서만 띄운다 | 없음. WAS는 아직 모의 대외기관을 부르지 않는다 |
| B | PH-33-② 송신 개발(10/13~) ~ 인프라 완성 전 | 지금 EC2 안의 두 번째 컨테이너. docker-compose `corebank-net`에서만 닿고 호스트 포트는 열지 않는다 | 이미지(이 jar를 감싼다) · CI push 단계 · compose 서비스 추가 — P5와 함께 |
| C | D-25 확정 · VPN 개통 뒤 | 온프레미스 대외·모니터링 VM | 같은 이미지를 VM에서 띄우고 WAS 접속 주소만 VM 사설 IP로 바꾼다 |
| C′ | VPN이 안 되면([O-10](README.md#8-미결)) | AWS 사설 서브넷 (B를 유지하거나 작은 인스턴스 하나) | WAS 접속 주소만 바꾼다 |

```
B:  [EC2] corebank-server ──corebank-net──▶ mock-external:9300   (외부 노출 없음)
C:  [EC2] corebank-server ──VPN──▶ [온프레미스 VM] mock-external:9300
```

- 이 PR은 A까지다. compose·CI·Dockerfile은 건드리지 않았고, 운영 이미지와 지금 EC2 배포에는 변화가 없다.
- B는 인프라 작업(다음 주)이 끝난 구조 위에 얹는다. compose와 CI는 P5 영역이고 `main` 머지가 곧 배포라서, 인프라 작업 도중에 먼저 고치지 않는다.
- C와 C′ 중 무엇이 되든 코드는 그대로다. D-25 확정([O-11](README.md#8-미결))을 기다리지 않아도 된다.
