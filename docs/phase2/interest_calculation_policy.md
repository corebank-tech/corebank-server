# 예·적금 이자 계산 정책 (PH-12)

> **문서 역할:** PH-12 이자 계산 및 PH-14·PH-15·PH-16 연동 시 적용할 계산 정책의 정본이다. 태스크별 범위·기한·완료 기준은 [tasks.md](tasks.md), 적수·거래일 용어는 [glossary.md](glossary.md), 원장 기표 계약은 [transfer_seam.md](transfer_seam.md)를 따른다.
>
> **관련 이슈:** [corebank-server #623](https://github.com/corebank-tech/corebank-server/issues/623) · **정책 정리:** 2026-10-15 · **대상:** 원화(KRW) 일반과세 예금·적금

## 1. 공통 원칙

| 항목 | 정책 |
|---|---|
| 이자 산정 기준 | `accumulatedDailyBalance`: 계산 기간 매일의 **일말 원장잔액** 합계 |
| 일수 방식 | **실일수/365**. 윤년에도 분모는 365로 고정 |
| 기간 경계 | `[fromInclusive, toExclusive)` — 시작일 포함, 종료일 제외 |
| 정상 만기 금리 | 가입 시점 스냅샷 `product_subscription.applied_rate` (연이율, **퍼센트 단위**: `3.70`은 연 3.70%) |
| 정상 만기 방식 | 상품의 `interestPayType`에 따라 `SIMPLE`(단리) 또는 `COMPOUND`(월복리) |
| 중도해지 | PH-16이 선택한 중도해지이율을 전체 실제 예치기간에 **소급 적용한 단리** |
| 이자 절사 | 단리는 전체 기간 끝에서 1회, 월복리는 **각 월 구간마다 원 미만 절사** (`RoundingMode.DOWN`) |
| 세금 | 지급 시 확정된 **총 세전이자**에 대해 소득세·지방소득세 각각 10원 미만 절사 |
| 숫자 형식 | 계좌 잔액·지급 금액·결과 `long`, 이율·중간 계산 `BigDecimal`; `double`/`float` 금지 |
| 지급 시점 | 월복리로 계산된 이자는 매달 원장에 기표하지 않고 **내부에서만 누적**. 실제 지급·기표는 PH-14·PH-15·PH-16 |

- 정상 만기에서 상품 기간별 기본금리(`product_rate_tier`)와 우대금리는 **가입 과정에서 확정**한다. PH-12는 가입 후 상품 마스터의 현재 금리로 재조회·재산정하지 않는다.
- 적금은 약정 납입액이나 정상 납입 가정이 아닌 **실제 원장에 기표된 납입액과 일자**를 따른다. 미납·지연 납입도 적수에 그대로 반영된다.
- 상품의 단리·복리 방식 수정 기능은 현 범위에 없다. `interestPayType`은 가입 스냅샷을 새로 만들지 않고 상품 마스터에서 읽되, **기존 가입 건이 있는 상품의 계산 방식은 변경하지 않는다**는 운영 전제를 둔다.
- 비과세·세금우대·세율 변경 이력·우대금리 조건 재판정은 이번 범위에서 제외한다.

## 2. PH-11 적수 계약

```java
long calculate(Long accountId, LocalDate fromInclusive, LocalDate toExclusive);
```

`AccumulatedDailyBalanceUseCase`가 반환하는 값은 다음과 같다.

```text
원장 적수 S = Σ (해당 날짜의 일말 원장잔액 B_d)
             d ∈ [fromInclusive, toExclusive)
```

- 같은 날 원장 기록이 여러 개라면 **최종 기표 후 잔액**만 사용한다. 거래가 없는 날은 직전 일말잔액을 이월한다.
- `account.balance`와 의미가 같은 **원장잔액**을 사용한다. 출금가능액(`availableBalance`)이나 보류액 차감 잔액을 이자 기준으로 사용하지 않는다.
- 현재 PH-11 구현은 `occurredAt` 날짜를 사용한다. #516(PH-41)·#515 완료 후 `tradeDate` 기준으로 전환하고 이자 테스트를 다시 검증한다. 날짜 원천 변경은 PH-12 계산 공식 변경과 분리한다.
- 적수는 `long`이므로 매우 큰 잔액·기간에서 범위를 넘지 않도록 보호해야 한다. PH-12에서 복리 가산 적수를 계산할 때에도 오버플로를 방지한다.

## 3. 단리 계산

`S = PH-11.calculate(accountId, 시작일, 종료일)`, `r = 연이율(%)`라 하면:

```text
세전이자 gross = truncWon(S × r / 36,500)
```

`36,500 = 365일 × 100(퍼센트 변환)`이며 `truncWon`은 **원 미만 절사**다.

- 납입액이 중간에 바뀌어도 같은 식을 적용한다. 개별 납입금마다 기간을 따로 계산하거나 개월 수를 가정할 필요가 없다.
- 이자를 매일 절사하지 않는다. **전체 구간 적수를 합산한 뒤 최종적으로 한 번만 절사**한다.
- 계산기간이 0일이거나 적수가 0이면 세전이자는 0원이다.

**검증 예시 — 기간 중 납입액 변화**

| 날짜 | 일말 원장잔액 |
|---|---:|
| 2026-04-01 | 1,000,000원 |
| 2026-04-02 | 2,000,000원 |
| 2026-04-03 | 2,000,000원 |

- 기간: `[2026-04-01, 2026-04-04)` (3일)
- 원장 적수: `1,000,000 + 2,000,000 + 2,000,000 = 5,000,000원·일`
- 연이율 `3.70%`의 세전이자: `truncWon(5,000,000 × 3.70 / 36,500) = 506원`

## 4. 월복리 계산

### 4.1 구간 생성

가입일 `D`를 기준으로 `D.plusMonths(n)`을 **항상 최초 가입일에서 직접** 계산한다(`n = 0, 1, 2, ...`). 최종 경계는 실제 계산 종료일을 넘지 않도록 자른다.

- 예: 2026-01-31 가입 → `2026-02-28` → `2026-03-31` → `2026-04-30`
- 존재하지 않는 날짜는 해당 월 말일로 보정한다. 앞 구간 끝에 `plusMonths(1)`을 반복하면 3월 경계가 28일로 밀릴 수 있으므로 사용하지 않는다.
- 최종 구간이 1개월 미만이라도 실제 일수만큼 이자를 계산하고 종료 시 원 미만 절사한다.
- 월별 구간은 중복·누락 없이 합쳐져 전체 계산 구간과 일치해야 한다.

### 4.2 월별 이자 산식

`A`를 **이전 구간까지의 누적 세전 복리 이자**(최초 0원), `d`를 해당 구간 실일수, `S`를 PH-11이 반환한 해당 구간 **실제 원장 적수**라고 한다.

```text
복리 계산용 적수 = S + (A × d)
구간 이자 I      = truncWon(복리 계산용 적수 × r / 36,500)
누적 이자 A     = A + I

최종 gross = 모든 구간 이자의 합 = 최종 A
```

- `A × d`는 **기존 복리 이자의 적수 효과**다. PH-11 원장 적수에는 미기표 복리 이자가 없으므로 별도로 더한다.
- `A`는 세전 금액이다. 월별로 원천징수하지 않으며, **세후이자를 복리 원금에 넣지 않는다**.
- 계산 중 생긴 복리 이자를 원장에 입금하거나 `account.balance`를 수정하지 않는다. 따라서 실제 원장 적수와 복리 계산용 적수는 구분한다.
- 구간 이자·누적액·복리 가산 적수의 산술 오버플로는 예외로 처리한다. 중간 곱셈은 `BigDecimal` 등 안전한 형식으로 계산한다.

**검증 예시 — 2026-01-31 가입, 2026-04-30 만기**

원장잔액이 내내 `1,000,000원`, 연이율이 `3.70%`이고 추가 납입·인출이 없다고 가정한다.

| 구간 `[시작, 종료)` | 일수 | 기존 누적 이자 A | 복리 계산용 적수 | 이번 구간 이자 |
|---|---:|---:|---:|---:|
| 01-31 ~ 02-28 | 28일 | 0원 | 28,000,000 | 2,838원 |
| 02-28 ~ 03-31 | 31일 | 2,838원 | 31,087,978 | 3,151원 |
| 03-31 ~ 04-30 | 30일 | 5,989원 | 30,179,670 | 3,059원 |

**최종 세전이자 = 2,838 + 3,151 + 3,059 = 9,048원.** 월복리 이자는 내부적으로만 누적한다.

## 5. 세금 및 결과 값객체

### 5.1 세금 계산

일반과세 이자에 적용하며, **월복리 구간별로 세금을 떼지 않고 최종 확정 세전이자 `gross`에 1회 계산**한다.

```text
incomeTax = trunc10(gross × 0.14)
localTax  = trunc10(incomeTax × 0.10)
tax       = incomeTax + localTax
net       = gross - tax
```

- `trunc10(x)`: **10원 미만 절사**. 예: `17,283.98 → 17,280`, `1,728 → 1,720`, `9 → 0`.
- 소득세는 14%, 지방소득세는 실제 원천징수하는 소득세의 10%다. 명목 총세율은 15.4%이지만 절사 때문에 실효 세율은 다를 수 있다.
- 소득세와 지방소득세는 **각각 별도로** 10원 미만 절사한다. 합산한 15.4%를 한 번 계산·절사하지 않는다.
- 이자소득은 「소득세법」 제86조의 **1,000원 미만 원천징수 소액부징수 예외에서 제외**된다. 임의로 1,000원 미만 세액을 0원으로 만들지 않는다.
- 세율(14%, 지방소득세 10%)은 YAML 설정값으로 관리한다. 10원 미만 절사 단위와 두 세금의 계산 **순서**는 이 문서의 정책으로 고정한다.

**검증 예시 — 세전이자 123,457원**

| 항목 | 계산 | 결과 |
|---|---|---:|
| 소득세 | `trunc10(123,457 × 14%)` | 17,280원 |
| 지방소득세 | `trunc10(17,280 × 10%)` | 1,720원 |
| 합계 세금 | `17,280 + 1,720` | 19,000원 |
| 세후이자 | `123,457 - 19,000` | **104,457원** |

위 월복리 예시의 `gross = 9,048원`이라면 소득세 `1,260원`, 지방소득세 `120원`, 총세금 `1,380원`, 세후이자 `7,668원`이다.

### 5.2 결과 계약

```java
InterestResult(gross, tax, net, appliedRate)
```

| 필드 | 의미 |
|---|---|
| `gross` | 최종 세전이자(원) |
| `tax` | 소득세 + 지방소득세(원) |
| `net` | 최종 세후이자(원) |
| `appliedRate` | **이번 계산에 실제 사용한** 연이율(퍼센트 단위, `BigDecimal`). 중도해지는 중도해지이율 |

`net = gross - tax`가 항상 성립해야 한다. 필요하면 내부적으로 소득세와 지방소득세를 따로 보관하되, 기존 PH-12 결과 계약은 유지한다.

**법령 및 검증 근거**

- [「지방세법」 제103조의13](https://law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1031061107): 원천징수 소득세의 10%를 개인지방소득세로 특별징수.
- [국세청 원천징수 개요](https://in.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7701&mi=2289): 지방소득세는 소득세액의 10%.
- [「국고금 관리법」 제47조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?lsJoLnkSeq=1031453581): 국고금의 10원 미만 끝수 처리. 각 원천세의 10원 미만 절사는 **팀에서 채택한 프로젝트 계산 정책**으로 명시한다.
- [「소득세법」 제86조](https://law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1021862057): 이자소득은 소액부징수 대상에서 제외.

## 6. 만기 및 중도해지

### 6.1 정상 만기 (PH-15)

- 종료일은 **약정 만기일**이다. 만기일 자체는 포함하지 않는다.
- 만기일이 휴일이어서 `MATURED` 상태 전이가 다음 영업일에 실행돼도 이자 계산 종료일은 변하지 않는다. 2차 정책상 만기 이후 추가 이자는 없다.
- 상품의 `interestPayType`과 가입 시점 `applied_rate`로 계산한다.
- 원장 기표·해지 상태 전이는 [transfer_seam.md §8](transfer_seam.md#8-입금-계약--예적금-이자만기해지-595) 계약을 따른다. 세후이자 지급(`INTEREST`), 원리금 전액 이체(`MATURITY`), 상품 계좌 잔액 0원 확인, `CLOSED` 전이를 같은 트랜잭션에서 수행한다.

### 6.2 중도해지 (PH-16)

- 종료일은 **실제 중도해지일**이며, 그날은 계산 구간에서 제외한다.
- PH-16이 실제 예치기간 구간에 해당하는 **중도해지이율**을 결정한 다음 PH-12에 전달한다.
- 해당 중도해지이율은 **가입일부터 해지일까지 전체 기간에 소급 적용**한다. 기존 약정금리로 계산한 이자를 일부 유지하지 않는다.
- 정상 만기 시 월복리 상품이더라도 중도해지 시에는 **처음부터 단리 방식**으로 재계산한다. 월복리 구간별 누적이자는 사용하지 않는다.
- 수수료 계산·중도해지이율표·해지 API·계좌 정리는 PH-16 책임이다. PH-12는 전달받은 금리·기간·계산 방식으로 **이자 금액**만 계산한다.
- 최종 원리금 이동은 `TERMINATION` 원장 출금·입금 2행으로 남기고, 상품 계좌 잔액 0원 확인 후 `CLOSED`로 전이한다. **잔액 0원만 직접 UPDATE하지 않는다.**

### 6.3 해지 시 원장·정보계 정합성

- `LedgerDepositUseCase.transferBetween()`은 상품 계좌 `WITHDRAWAL` 1행과 고객 계좌 `DEPOSIT` 1행을 남긴다. `transaction_type`은 만기해지 `MATURITY`, 중도해지 `TERMINATION`이다.
- 해지 기표의 `transfer_id`는 `NULL`이므로 PH-75·PH-76은 `transfer` 조인만으로 해지 거래를 추출하지 않는다.
- 완료 조건: 상품 계좌의 `account.balance = 0`이고 해당 계좌 **원장 부호 합계도 0**, 수취 계좌 역시 원장 합계와 잔액이 일치한다. 실제 통합 검증은 PH-15·PH-16에서 수행한다.

## 7. 구현 경계 및 검증 항목

### 7.1 책임 분리

| 영역 | 책임 |
|---|---|
| PH-11 | 원장 적수 조회 (`AccumulatedDailyBalanceUseCase`) |
| PH-12 도메인 | 단리·월복리·절사·세금 계산의 **순수 계산 로직** |
| PH-12 애플리케이션 | PH-11 구간 조회, 계산 입력(기간·금리·방식) 구성, 도메인 계산기 호출 |
| PH-14 | 이자 지급·원장 기표·원천징수 분개. `InterestResult` 재사용 |
| PH-15 | 만기 감지·만기해지 오케스트레이션 |
| PH-16 | 예치기간별 중도해지이율 선택·수수료·중도해지 오케스트레이션 |
| PH-41 (#516·#515) | 원장 적수의 날짜 기준을 `tradeDate`로 이행 |

기존 `SubscriptionMaturityCalculator` 및 FE 가입 예상 만기금액은 이번 PH-12 범위에서 **참고값으로 유지**한다. 기존 서버 예상식과 FE 예상식도 서로 다르므로 실제 지급액과 동일하다고 보장하지 않으며, 계산식 통일은 후속 작업으로 분리한다.

### 7.2 테스트 기준
