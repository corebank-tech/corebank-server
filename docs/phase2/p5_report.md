# P5 배치·인프라 리포트 (P5-RPT)

> COB 기준선과 대사 원인, 3-Tier 컷오버와 온프레미스 VM 승격·철거, 정보계 ETL·API, 하이브리드 VPN과 장애, 시연 환경(AI Agent 2종 포함)을 한 장으로 묶는다. PH-48 발표 자료의 입력이다(#857).
> 수치마다 원 문서를 단다. **확정**은 원 문서에 측정 조건과 함께 기록된 값이고, **참고값**은 표본이 적거나 조건이 달라 기준선으로 쓰지 않는 값이다. **미확정**은 원인이나 크기를 확인하지 못한 것이다. 시각은 모두 KST다.
> 이 리포트는 새로 잰 것이 아니라 아래 문서들을 묶은 것이다. 같은 수치를 다시 집계하지 않고 그대로 옮긴다.

## 2. COB 기준선과 대사 원인 (PH-43 · PH-45 · #856)

### 2-1. 기준선

- 측정 전용 실행기 대신 **운영 COB가 매일 밤 남긴 기록**(`batch_execution_history`, `business_date_cutoff`)을 읽기 전용으로 조회했다. 실행기를 돌리려면 영업일을 되돌리는 경로가 운영 코드에 생기고 컷오버(10/27 ~ 28) 측정 금지 기간과 겹쳤기 때문이다. P4의 PH-38 실측(1,188.1초)과 운영 첫 COB(1,183.6초)가 약 0.4% 차이라 운영 기록을 기준선으로 써도 된다고 판단했다.
- 6점(10/26 ~ 10/30, 11/2): 평균 1,216.2초, 중앙값 1,222.8초, 표본 표준편차 약 23.0초(평균의 약 1.9%). COB 시간 대부분이 대사다(1,183.6초 중 만기 감지는 약 1.7초).
- p95 · p99(1,238.0 · 1,238.2초)는 점이 6개라 최대값에 가깝다. 규칙을 맞춘 참고값이고 꼬리 값이 아니다.
- 대사 시간이 월 → 목으로 날마다 늘었다(1,183.6 → 1,238.2초, +4.6%). 같은 날의 데이터 규모를 세지 않아 원인은 **미확정**(데이터 증가 추정)이다.

### 2-2. 릴리스 3 이후와 청크 60초 제한

- 릴리스 3(11/3)에는 청크 실패 격리(#692, PR #850)만 들어갔다. 속도를 바꾸는 변경은 없어서 "개선 후"가 아니라 "릴리스 3 이후"로 적는다.
- 이 제한은 계좌 1,000개 묶음을 60초 안에 못 읽으면 마감을 멈춘다. 기존 환경은 11/3 · 11/4 밤 두 번 이 제한에 걸려 멈췄다(150 · 151초, `HALTED`). 11/5 저녁에 제한을 1,800초로 올리고 앱 컨테이너만 다시 만들어(코드 변경 없음) 풀었다. 이후 점은 기준선 범위(1,183.6 ~ 1,238.2초) 안이다.
- 멈춘 COB의 다음 밤이 같은 영업일을 먼저 재시도하고 새 COB를 시작하지 않는 동작(#663과 같은 동작)이 11/3 만기 처리를 약 2일 늦췄다. 밀린 분이 다음 실행에 함께 처리되므로 누락은 없다(코드 확인, 계좌별 결과는 조회하지 않았다).
